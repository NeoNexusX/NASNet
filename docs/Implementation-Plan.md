## 当前代码布局

```text
NASNet/
├── Cargo.toml                 nasnet 包的配置
├── Cargo.lock                 依赖锁文件
├── src/
│   ├── main.rs               12 课完整安排，唯一二进制 crate 的根文件
│   ├── demo.rs               调用模型的学习演示
│   ├── model.rs              model 模块入口，只声明模块并统一导出
│   └── model/
│       ├── device.rs         设备及其地址、连接列表的管理
│       ├── address.rs        地址模型和 Host 校验
│       ├── connection.rs     连接记录、配置枚举和校验分派
│       ├── connection/
│       │   ├── nfs.rs        NFS 配置、身份、版本及校验
│       │   └── smb.rs        SMB 配置、身份、方言及校验
│       └── error.rs          统一错误类型及其展示
└── docs/
    ├── NAS-Client-Architecture.md
    ├── Rust-Learning-Plan.md
    ├── Implementation-Plan.md
    └── lessons/
```

当前使用一个包、一个二进制 crate，采用 Rust 2018 edition 和 non-mod-rs 布局：`src/model.rs` 是 `model` 入口，`src/model/` 只放其子模块。后续模块也使用同名 `.rs` 文件与同名子目录，不创建 `mod.rs`。`main.rs` 顶部保存长期课程安排，下方声明模块并选择演示。`lesson01`/`lesson02` 运行第 1 课 A/B，`lesson03`/`lesson04` 运行第 2 课 A/B，`lesson05` 运行第 3 课 A；默认仍为第 1 课 A。演示小节编号与大课课号分开。

模型按业务对象划分：`device.rs` 管理设备拥有的地址和连接列表，`address.rs` 校验单条地址与 Host，`connection.rs` 校验单条连接并分派给 NFS/SMB 配置。协议配置及其校验分别位于 `model/connection/nfs.rs` 和 `smb.rs`，统一错误定义位于 `model/error.rs`。调用方的 `crate::model::{...}` 导入路径保持一致。

后续优先增加 `store`、`router`、`nfs`、`smb` 等模块，形成明确的职责边界；出现独立构建或复用的实际需求时再讨论拆包。最终桌面壳和独立后台的进程与构建组织，在对应阶段确定。

当前代码只需 Rust，不会编译 C。C FFI 练习和协议库构建安排在 M5。

## M1 的实现范围

`Address` 包含 `id`、`host`、`priority`；`Device` 包含 `id`、`name`、`addresses`。设备拥有地址，地址拥有各自的字符串。创建、添加、计数和改名由学习者实现并通过验收，终端展示通过只读借用读取数据。

地址与协议校验已经实现；没有磁盘存储、网络访问或挂载。M1 展示按添加顺序，M2 已完成查找和稳定优先级排序。进入第 3 课后设备字段及两个列表都私有，展示改用只读方法，旧的无校验添加入口已移除。

## 已完成：M3 的模型封装部分

第 2 课地址与协议校验已检查通过，失败添加不会改变保存结果。[第 3 课 A 讲义](lessons/05-encapsulation-and-lifetimes.md)中的 `try_update_address`、`remove_address`、`find_connection`、`try_update_connection` 和 `remove_connection` 均已完成。原位置替换、失败不改原值、删除交还所有权和借用返回值已通过演示核对。

`Device::try_add_connection` 的流程已提供：先校验，再检查同设备内连接 ID 是否重复，最后保存。设备内嵌拥有连接，因此当前内存模型不重复保存 `device_id`；持久化时再建立关联。同一设备可保存多个导出或共享，它们复用地址列表，各自拥有配置与身份。

当前只检查本地格式。协议版本、方言表达请求意向，实际后端支持和认证结果在 M5 检查；SMB 密码引用尚未接入系统凭据存储。公开候选值提交给设备时校验，保存后仅能只读借用。模型更新、删除和查找已完成，编译、格式和 Clippy 检查均通过；行为继续使用演示和明确预期结果核对。

## 后续实现需要保持的约束

- 地址只保存 IP/域名与优先级，不增加网络用途或环境分类。端口、认证和远程路径放在协议配置中。
- NFS 和 SMB 使用独立的身份与权限模型。NFS 的 UID/GID 不等于 SMB 账号，也不意味着获得服务器权限。
- 会话状态按协议连接保存；不把某一个协议的成功当成另一个协议成功，不在 SMB/NFS 之间自动切换。
- 原生库版本、绑定和构建选项一起维护。C 指针和释放责任限制在安全封装内部，不把未知线程安全性的 C 上下文直接跨任务共享。
- 目录浏览、系统挂载分别管理会话和能力。权限修改结果未知时先查询，不直接重复修改。
