## M1 的实现范围

`Address` 包含 `id`、`host`、`priority`；`Device` 包含 `id`、`name`、`addresses`。设备拥有地址，地址拥有各自的字符串。创建、添加、计数和改名由学习者实现并通过验收，终端展示通过只读借用读取数据。

基础地址校验已经实现。`Device.connections` 和 NFS/SMB 配置结构也已加入，协议校验仍是练习占位；没有磁盘存储、网络访问或挂载。M1 展示按添加顺序，M2 已完成查找和候选地址排序。地址字段暂时公开，连接列表为私有字段，通过只读切片观察。

## 当前：M3 的协议配置部分

第 2 课 A 的基础地址校验已检查通过，失败添加不会改变保存结果。按[B 小节讲义](lessons/04-protocol-configs.md)填写 `NfsConfig::validate`、`SmbConfig::validate` 和 `ProtocolConnection::validate`。通过借用枚举，按实际协议调用对应校验。

`Device::try_add_connection` 的流程已提供：先校验，再检查同设备内连接 ID 是否重复，最后保存。设备内嵌拥有连接，因此当前内存模型不重复保存 `device_id`；持久化时再建立关联。同一设备可保存多个导出或共享，它们复用地址列表，各自拥有配置与身份。

当前只检查本地格式。协议版本、方言字段表达请求意向，实际后端支持、服务器协商及认证结果在 M5 检查；SMB 密码引用尚未接入系统凭据存储。地址的旧方法和公开字段暂时保留，所以此时还没有“所有地址写入都受校验”的保证；本轮完成后继续收紧地址入口。演示和预期结果替代课程测试。

## 后续实现需要保持的约束

- 地址只保存 IP/域名与优先级，不增加网络用途或环境分类。端口、认证和远程路径放在协议配置中。
- NFS 和 SMB 使用独立的身份与权限模型。NFS 的 UID/GID 不等于 SMB 账号，也不意味着获得服务器权限。
- 会话状态按协议连接保存；不把某一个协议的成功当成另一个协议成功，不在 SMB/NFS 之间自动切换。
- 原生库版本、绑定和构建选项一起维护。C 指针和释放责任限制在安全封装内部，不把未知线程安全性的 C 上下文直接跨任务共享。
- 目录浏览、系统挂载分别管理会话和能力。权限修改结果未知时先查询，不直接重复修改。
